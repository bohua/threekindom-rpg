# 0.2 新系统设计：战场事件、护卫目标与友军、记忆写入最小版

日期：2026-10-25　状态：**设计稿 v1.0（已按 CD-GDD-ALIGN、LP-FEASIBILITY 评审修订）**　牵头：systems-designer；评审 creative-director、lead-programmer
依据：`CHAPTER1_RISE_SCRIPT.md` §4 第二、三节，§5 战斗 4–6，§13 /gate-check（进入 0.2 制作前需要这三份设计）；`V1_SPEC.md` §4 战斗流程、§9 存档。

总原则：
- 三个系统都**数据驱动**：规则写在战斗配置／剧情数据里，代码只提供通用的“条件 → 动作”执行器，0.3–0.5 的波次、撤离、客将可以在同一套上加条件和动作，不再改框架。
- 不加随机：沿用 V1“无暴击、无闪避随机”的可预测战斗。
- 与战斗形式无关：触发条件只用“回合数、单位兵力比例、单位撤退”这类对列回合制和日后半即时战棋都有的量，避免以后换战斗形式时重写。

## 1. 战场事件

### 1.1 玩家体验

战斗打到一半，局势按剧情变化：火起、援军到、敌将溃走。玩家在**事件发生前一回合**就能看到预告（“火攻将于下回合发动”），学会根据事件调整打法。

### 1.2 规则

一场战斗的配置里有一个 `events` 列表，每条事件：

| 字段 | 说明 |
| --- | --- |
| `id` | 事件 id（战斗内唯一） |
| `when` | 触发条件，0.2 支持三种：`turn_start(N)`（第 N 回合开始）、`unit_hp_below(unit, ratio)`（**跨过阈值时触发**：动作前 ≥ 阈值、动作后 < 阈值，一击打到 0 也算）、`unit_retreated(unit, reason?)` |
| `once` | 默认 true，触发一次 |
| `actions` | 依次执行的动作列表 |

0.2 需要的动作：

| 动作 | 说明 |
| --- | --- |
| `banner(text)` | 屏幕中上方横幅，1.5 秒，可按键加速 |
| `dialogue(id)` | 播一小段战中对白（2–4 句），播放时战斗暂停 |
| `apply_status(side_or_unit, status, turns)` | 给一方全体或某单位加状态 |
| `damage_ratio(side_or_unit, ratio)` | 按最大兵力比例扣兵力（不致死：最低留 1） |
| `fx(id)` | 播一段特效（火光、骑兵剪影横扫），不影响判定 |
| `retreat(unit_or_side)` | 指定单位或一方全体撤退，撤退原因记为“溃走”（区别于兵力归零的“被击破”）；会触发 `unit_retreated`，可用 `reason` 过滤 |
| `end_battle(result)` | 立即结算 `victory` 或 `defeat`，**中止**本次剩余动作和事件队列 |
| `set_objective(text)` | 更新回合目标栏文字 |

**结算管线（写死，不可配置）**：
1. 一次动作（攻击、技能、道具；全体技能算一次）结算完伤害与状态；
2. 兵力归零的单位标记撤退（原因“被击破”）；
3. 胜负判定（顺序见下）；
4. 本次动作产生的条件（跨阈值、撤退）按发生顺序进入**事件队列**，先进先出执行；每个事件的动作全部执行完，再做一次完整胜负判定；
5. 事件动作产生的新条件也进队列，**递归深度上限 3**，超过时只记日志、不再触发；
6. 下一次动作。

`turn_start(N)` 在回合开始时执行，**早于敌方与友军 AI 读取回合开始状态**，再进入玩家下令。事件动作不消耗任何单位的行动。动作是**可等待的**（对白、横幅、特效播完才继续，按键可跳过）。

**胜负判定顺序**：① 我方（Player 阵营）全撤 → 失败；② 失败条件（护卫目标撤退、`end_battle(defeat)`）→ 失败；③ 敌方全撤或 `end_battle(victory)` → 胜利。失败优先，避免“同归于尽算赢”。友军不计入①。

**实现接口**：条件与动作各一个注册表（字符串 id → 实现类），战斗配置用 ScriptableObject，导入时校验：引用的单位 id 存在、`turn_start` 的 N 不重复冲突、`end_battle` 后没有多余动作。回合目标栏文字用模板（如“坚持到第 {N} 回合”“剩 {R} 回合”），由执行器填数字。

**重试与存档**：事件触发记录只存在本场战斗的运行状态里，不进存档；战败重试还原战前快照，事件从头计。

### 1.3 新状态：混乱

| 项目 | 规则 |
| --- | --- |
| 效果 | 物攻、计攻各 −30%，物防 −20%；**不做随机乱打**（V1 不加随机） |
| 持续 | 按 V1 规则：包含施加当回合，回合结束减 1 |
| 叠加 | 沿用 V1“同属性同方向只取较强” |
| 显示 | 单位头顶状态图标＋状态栏文字“混乱（剩 N 回合）” |
| 来源 | 0.2 只有战场事件施加；技能不施加 |

### 1.4 战斗 4 颍川夜战的配置

```
events:
  - id: fire_preview   when: turn_start(2)  actions: [set_objective("坚守！火攻将于下回合发动")]
  - id: fire           when: turn_start(3)
      actions: [fx(fire_wall), banner("火起！"), dialogue(b4_fire),
                apply_status(enemy_all, 混乱, 2), damage_ratio(enemy_all, 0.10),
                set_objective("援军将至：坚持到第 5 回合")]
  - id: cavalry_preview when: turn_start(4) actions: [set_objective("红旗骑兵将于下回合杀到")]
  - id: cavalry        when: turn_start(5)
      actions: [fx(red_cavalry_sweep), banner("援军杀到！"), dialogue(b4_cavalry),
                retreat(enemy_all)]          # 敌方全撤即胜利，无需 end_battle
```

全灭提前胜利照常有效。

## 2. 护卫目标与友军单位

### 2.1 玩家体验

“救人”在机制上成立：一支不听你指挥的友军站在我方阵中，敌人盯着它打，你要决定先救人还是先杀敌。这是刘备“仁义”的第一次机制表达（0.3 的“众望”在这上面扩展）。

### 2.2 规则

| 项目 | 规则 |
| --- | --- |
| 阵营 | 三方阵营枚举 Player／Ally／Enemy。敌方的目标池＝Player＋Ally；我方单体恢复与增益的目标池＝Player＋Ally；我方攻击目标池＝Enemy |
| 站位 | 友军站在我方阵列，单独一个位置（第 4 位，排在我方 3 人之后），不占出战名额 |
| 操作 | 玩家**不能下令**；友军用固定 AI 行动 |
| 友军 AI（董卓本阵） | 自身兵力 ≥ 50%：普通攻击当前兵力最低的敌人（同兵力按站位顺序）；< 50%：防御（按先行指令处理）。读取回合开始时的状态 |
| 目标转移 | V1 §4 第 6 条“目标已撤退时转向第一个存活敌人”：对敌方来说按目标池站位顺序，Player 在前、Ally 在后 |
| 被我方支援 | 我方的单体恢复技能（刘备“整队”）、道具“军粮”可以选友军为目标；其他增益技能若为“一支友军”，同样可选 |
| 敌方 AI | 新增目标规则“优先护卫目标”：配置了 `focus_escort` 的敌人优先打护卫目标；战斗 5 中张角的亲卫×3 有此标记，张角本人按原规则 |
| 护卫目标 | 战斗配置里 `escort: [unit]`；该单位撤退＝**立即失败** |
| 行动顺序 | 友军按速度正常参与排序，同速时我方 → 友军 → 敌方 |
| 奖励与成长 | 友军不吃经验、不进编队、不进存档 |
| 显示 | 友军兵力条用绿色边框＋“护”字标记；回合目标栏显示“保护董卓本阵（剩 N 回合）” |

### 2.3 战斗 5 广宗救董卓的配置

```
allies: [dongzhuo_army]          escort: [dongzhuo_army]
enemies: [zhangjiao, guard×3(focus_escort)]
events:
  - id: hold       when: turn_start(1) actions: [set_objective("保护董卓本阵：坚持到第 4 回合结束")]
  - id: hold_end   when: turn_start(5) actions: [banner("张角兵败退走"), retreat(enemy_all)]
  - id: early_win  when: unit_hp_below(zhangjiao, 0.30)
      actions: [dialogue(b5_zhangjiao_flee), retreat(enemy_all)]
```

“第 4 回合结束”用“第 5 回合开始”实现，避免新增回合结束触发点。

**数值意图**：董卓本阵兵力约为刘备的 1.5 倍，物防偏低；亲卫三人集火时，不支援的话约在第 3 回合归零——逼玩家至少用一次整队或军粮，或用张飞“威慑”压低敌方物攻。具体数值在 balance-check 时调。

## 3. 记忆写入最小版

### 3.1 玩家体验

做过的选择会被人物“记住”。每次写入时右下角提示“××记住了这件事”，武将界面“记忆”栏能看到“卢植记得：……”；**本版内第一次回收**在 C13：关羽、张飞的送行台词随选择②变化。0.3 起更多回收（董卓在会盟时认出“涿郡白身”等）。

### 3.2 规则（最小版）

是 AI 人物命运设计稿中“记忆”的最小子集：只有**标记**，没有态度数值、没有命运重算。

| 字段 | 说明 |
| --- | --- |
| `who` | 记住的人物 id（卢植、董卓、曹操、孙坚、刘备、关羽、张飞） |
| `key` | 记忆 id，如 `luzhi_cart` |
| `value` | 选项值，如 `A_trust` / `B_escort`；无选择的事件为 `seen` |
| `node` | 写入时的主线节点（N1／N2） |
| `text` | 显示给玩家的一句话 |

- 写入点：必做 9 条，选做 C5 加 1 条（见 §3.3）；全部无条件写入，有选择的写选项值。
- 同一 `who`＋`key` 只保留最后一次写入（重玩同一段落时覆盖，不重复）。
- 存档：存进当前存档的剧情状态，和任务完成标记同一个写入事务；**不用跨存档全局标志**（V1_SPEC §9 已定）。读更早的存档后再做另一个选择，以当前存档为准。
- 显示（必做）：写入时右下角提示 2 秒；武将界面“记忆”栏列出该人物所有记忆的 `text`（版式由 Codex 设计图定）。
- 查询接口：剧情条件可以写 `memory(who, key) == value`；0.2 在 C13 使用。

## 4. 附：等级与经验扩展

- 等级上限 5 → 7；累计经验表 0／10／30／60／100／150／210。
- 属性成长沿用 V1 每级固定增加；兵力、技力、物攻等派生公式不变。
- 战斗 4／5／6 经验 40／50／60，到 5／6／7 级。0.2 不加新技能。

## 5. 附：行军过场、进度步骤与存档迁移

**行军过场**
- 数据：每段 `{from_node, to_node, path_nodes[], year_label, via_event?}`；节点位置用天下图上的**归一化坐标（0–1）**，换图只改节点表。
- 表现：天下图局部缓慢平移，棋子沿虚线移动，顶部显示年号（中平元年·184），5–8 秒；按确认键跳过——**有途经事件时跳到途经点停下弹出选择**，否则直接到终点。
- 兜底：没有行军资源时显示“地名＋年号”字卡 2 秒，数据接口不变。
- `via_event`：0.2 只有广宗→安喜段的“绕道南阳”（C5）。
- 足迹记录移到 0.5，0.2 不做。

**进度步骤（不能回访）**
- 在年份节点状态机里加 `chapter_step`（如 `zhuojun_done`、`camp_left`、`yingchuan_done`、`guangzong_done`、`anxi_arrived`、`anxi_left`）。场景加载前查步骤：已过的场景不可作为存档落点或加载目标。确认框按步骤列出未完成委托。
- 段落自动存档：到达卢植大营、到达安喜时各写一次自动档（滚动档沿用 V1 §9）。

**存档版本升级**
- 存档版本号 +1；0.1 存档读取时迁移：`chapter_step` 由 0.1 的“三战完成／结尾完成”标记推出（结尾完成的档从 C1 开始），记忆为空、委托为空、等级与经验保留。迁移后不改原文件，另存为新版本。
